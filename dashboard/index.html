2 · Monetização · Google AdMob

Configure as unidades de anúncios do projeto selecionado. As alterações são salvas no GitHub e só afetam o aplicativo quando ele estiver integrado ao contrato e receber uma nova compilação.

Selecione um projeto Android para carregar as configurações.

Configuração salva na branch selecionada, não automaticamente na branch principal. O APK só incorpora as escolhas após uma nova compilação.

Em teste, os IDs demonstrativos oficiais substituem os cadastrados durante a execução. A publicação com IDs de demonstração deve ser bloqueada no aplicativo.

O App ID identifica o aplicativo, não uma unidade. Alterá-lo exige nova compilação e configuração Android adequada para SDK e UMP.

Outros formatos de anúncio (opcional)

A concessão de moedas exige confirmação do evento de recompensa e controles antifraude no aplicativo ou backend. Configurar o ID não libera moedas automaticamente.

3 · Configurar e compilar

A compilação usará a branch escolhida no primeiro card. Modificações nos IDs de anúncios exigem novo APK/AAB.

Configurações avançadas (pasta, módulo, Java, ZIP)

Automático preserva builds Android sem flavors. Para Kotlin Master escolhe devDebug para APK de teste e prodRelease para AAB/release.

O ZIP será salvo no repositório selecionado e extraído pelo GitHub Actions. Em repositórios públicos, o conteúdo poderá ficar público. Para projetos maiores, use um repositório já preenchido.

5 · Assinatura · somente após compilar

Escolha um AAB sem assinatura no histórico da opção 4 ou informe abaixo o número da execução e o nome exato do artefato. A assinatura acontece no GitHub Actions.

Selecione o aplicativo para verificar se os Secrets estão cadastrados. O GitHub não mostra seus valores.

🔑 Gerar chave e configurar assinatura automaticamente

Somente para a primeira publicação. Se o aplicativo já foi publicado ou a chave já existe, não gere outra. Reutilize a chave original.

Guarde sua senha de recuperação! Não é possível recuperá-la do GitHub. Mantenha em um gerenciador de senhas privado.

O arquivo de recuperação contém a senha em texto simples. Guarde-o em local seguro e privado.

3. Recupere o JKS. Aguarde a geração no GitHub Actions, baixe o ZIP e extraia upload-key.jks.ubenc. Este é o backup criptografado da chave, não um AAB.

O desbloqueio acontece somente no seu navegador HTTPS.

4. Guarde e configure. Baixe a sua chave JKS e faça backup antes de ativar a assinatura.

Os dados são criptografados no navegador usando a chave pública do GitHub, antes do envio.

Configuração manual (avançado)

Crie ANDROID_KEYSTORE_BASE64 (Base64), ANDROID_KEYSTORE_PASSWORD (senha), ANDROID_KEY_ALIAS (upload) e ANDROID_KEY_PASSWORD (mesma senha).

Já tenho um arquivo .jks/.keystore usado em outro sistema

Para atualizar um app da Google Play, reutilize o JKS original. Não substitua uma chave existente sem confirmar sua identidade.

Modo manual (avançado)

Se você já cadastrou ANDROID_KEYSTORE_PASSWORD pelo GitHub, use o gerador antigo, sem sobrescrever chaves de aplicativos publicados.
